# Run & Debug Guide

Load before building, running, or capturing screenshots.

- `just generate` → `Hearvia.xcodeproj`; `just build` builds both apps; `just run-mac` launches the Mac app binary with `--verbose` (JSON events on stdout; fine for logs, but permissions attach to the terminal, see below); `--autostart` starts capture at launch and skips the first-run permission explainer (`defaults delete dev.hewig.hearvia hearvia.hasExplainedPermissions` shows it again). `hearvia.menuBarOnly` selects menu-bar-only mode. `--source=microphone`, `--source=all` or `--source=<pid, bundle ID or name>` picks what `--autostart` captures. Launch with `open -n -a <app> --stdout <log> --args …` rather than the binary, so macOS asks for permissions on Hearvia's behalf, not the terminal's.
- iPhone: `just install-ios` builds, installs and launches on the paired device (set `HEARVIA_DEVICE` to its UDID; `xcrun devicectl list devices` shows it). Pass launch arguments after `--` with `xcrun devicectl device process launch … -- -hearvia.appearance light`. In Debug, `-hearvia.autostart microphone` (or `otherApps`) starts listening at launch; combine with `-hearvia.engine onDevice -hearvia.sourceLanguage "" -hearvia.targetLanguage zh` and read `Documents/Evidence/*.jsonl` (`xcrun devicectl device copy from --domain-type appDataContainer --domain-identifier dev.hewig.hearvia --source Documents/Evidence …`).
- Screenshots: `xcrun devicectl device capture screenshot --device <udid> --destination out.png` (the phone must be unlocked; a locked phone returns a black image). Mac windows: `screencapture -o -l <windowID>`; never capture the whole screen, it includes the user's other apps.
- Simulators: iOS 27.0 and 27.1 runtimes with "Hearvia iPhone", "Hearvia 6.9", "Hearvia iPad 13" and "Hearvia Duo" (fold it in Device Hub). The Simulator has no ScreenCaptureKit, PiP or on-device speech, so verify capture and translation on the device.
- PoC diagnostics are in Debug builds of the iOS app under Settings → Developer tools; logs export as JSONL from there. Release builds have no developer UI and write no log file.
- Realtime engine log events: `translation_connected`, `translation_session`, `translation_paused` / `translation_resumed` (silence), `translation_rotated` (before expiry), `translation_error`, `translation_closed`.
- Keep scratch output outside the workspace tree; jj snapshots untracked files into the change.
